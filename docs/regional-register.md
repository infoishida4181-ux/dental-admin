# 歯科施設基準データの更新（関東信越）

出典：[関東信越厚生局・施設基準の届出受理状況](https://kouseikyoku.mhlw.go.jp/kantoshinetsu/chousa/kijyun.html) の「届出受理医療機関名簿／歯科（ZIP）」。一覧は基準日現在の公表資料であり、辞退や廃止を確定する資料ではありません。

## 会員の操作

医院名を押し、都道府県と7桁の医療機関番号を保存します。旧東京プロフィールは再登録不要です。「施設基準の更新」で自院の都道府県だけを読み込みます。未対応県は「データ準備中」です。比較だけでは台帳を書き換えません。初回取込の「置換」は明示確認を伴う別操作です。都道府県変更前は同一アプリの他のタブを閉じてください。

## 管理者の操作

1. 管理者画面の「関東信越 歯科施設基準データ一括更新」に公式ZIPを投入します。個別XLSXは従来のプレビューです。新しいファイルを選び直すと前のWorkerを終了します。
2. 各都県の基準日・作成日・旧新件数・追加／変更／消失候補・重複数を確認します。完全重複候補は元のまま保持し、行番号を review.json に残します。届出欄がすべて空の医院は届出0件です。10都県すべて成功しない限り公開候補を出力しません。件数減少の許容率（初期値10%）は運用上の警戒値です。閾値変更は根拠を記録してから行ってください。
3. ZIPを保存しても**未公開**です。ブラウザにはGitHub書込API・トークンはありません。アプリの管理者パスフレーズはリポジトリ権限とは無関係です。

## 配布担当者の手順（方式A）

最新mainのクリーンな作業コピーで実施。旧manifest・JSONは削除しません。公式ZIPと候補ZIPはリポジトリに入れません。Node 22以上、Chrome/Edgeの現行版を使用してください。

1. 公式配布元のZIPと対象月を確認し、同じソースを独立に再変換： node tools/register-release.cjs SOURCE.zip NEW_STAGING_DIR 10 。出力先は未使用のディレクトリ。容量不足や失敗時は本番にコピーせず、新規ディレクトリで再試行します。
2. node tools/check-register-package.cjs REVIEWED.zip NEW_STAGING_DIR を実行し、直前のmanifest、差分、10ファイルのバイト、SHA-256、配布パスを照合します。比較元が変わっていればやり直します。更新日時を除き候補と再生成manifestが一致しなければ公開不可です。
3. 前版のmanifestをGitで保持し、新しい不変JSONのみを追加して通常push。Pages成功と公開URLで**全ファイルのSHA-256**を確認します。この段階では現行manifestは変えません。
4. 公開直前に上記チェックとリモートHEADを再照合し、検証済みのローカル再生成manifestを最後に切り替えます。通常pushを使い、非fast-forwardは停止。Pagesの新デプロイ、公開manifestと都県別検索を検証します。保護ブランチではレビュー済みPRを使用します。
5. 問題時は**manifestだけ**を前の正常版へ戻す変更を新しいコミットで公開します。古いJSON、証明書DB、ジャーナル、医院データは触りません。コード修正は現行の復旧ローダーを残したまま行います。

## 形式と制限

- manifestVersion 2 の datasets で都道府県ごとの active を1件に限定。従来の activeDatasetId は東京を示し、旧manifest・旧東京JSONも読み込めます。都県コードと7桁番号は別の文字列として保持。点数表コードを推測して合成しません。
- ファイルは prefectures/都県コード/dental-版-SHA256先頭16桁.json。照合には**64桁全体**を使用します。同じ版で別内容の差し替えは拒否。既存版を直接編集しないでください。
- 外側ZIP・内側XLSXにそれぞれエントリ数、展開量、パス、圧縮方式等の制限。読み取るエントリはCRCと実展開サイズも検証。XMLはWorker内で逐次解析し、DTD・数式・不明な必須列は拒否します。ふりがなと印刷設定はデータとして取り込みません。ZIP投入時は外部へ送信せず、同一配信元の比較用データのみ取得します。
- 変換のみローカル同梱の sax 1.6.1（assets/vendor/sax/LICENSE.md）を使用。会員の起動時には読み込みません。出力は既存 grouped-by-clinic 形式。地域を追加するときは帳票ごとの入力アダプターと受入試験を追加し、共通のmanifest・配布・検索形式を利用します。
- ワンクリック公開には、管理者の本人認証・権限確認・監査・GitHub Appの短期トークンを扱うサーバー側が必要です。静的サイト上のパスフレーズで代用しません。
